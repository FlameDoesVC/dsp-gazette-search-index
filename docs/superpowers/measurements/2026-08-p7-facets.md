## The two named queries

Spec 8.3 names these specifically. If they do not work, the feature does not.

| Query | Dynamic facets returned, in order | Right? |
|---|---|---|
| power supply | brand, power | voltage/current dropped -- see below |
| iphone | power, brand | |
| washing machine | (none) | no facetable specs in the result set |
| ac | (none) | short/ambiguous query; sparse spec coverage |
| laptop | brand, type, storage_gb, screen_size, power | richest surface, as expected |

"power supply" does not surface voltage even though `voltage` spec rows exist.
That is step 3 working as designed, not a miss: Maldivian mains voltage is a
standard 240V, so over the candidate set voltage is effectively constant and a
voltage filter would be a dead checkbox. The 20-result sample shows voltage
with a single distinct value for exactly this reason.

Budget 600ms p95. The slow latency test (`-m slow`) measures 90ms p95 at 20k
docs after ANALYZE; the 2s failure it originally produced was an artifact of
stale planner stats in the shared test DB, not a real cost. Spec 16.4's
Meilisearch re-entry condition is not triggered.
